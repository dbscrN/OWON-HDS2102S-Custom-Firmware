# Инструкция для агента

Проект — модификация прошивки V4.7.1 осциллографа-мультиметра OWON HDS2102S (вариант `HDS2102S_LS`). Исходников прошивки нет: работа идёт с бинарным образом, новый код дописывается на C и встраивается перехватом вызовов. Проверить результат можно только на приборе владельца — у тебя его нет.

Сначала прочитай `docs/NOTES.md`: там все адреса, форматы и протоколы. Этот файл — про то, как работать.

## Правила, которые нельзя нарушать

- **Ты не можешь проверить прошивку.** Не пиши «работает», пока владелец не подтвердил на приборе. В отчёте всегда разделяй: что проверено статически, а что — догадка.
- **Каждая прошивка — риск кирпича.** Способ восстановления без программатора неизвестен. Перед выдачей сборки проверь всё, что можно проверить без прибора (см. «Проверка перед выдачей»).
- **Неизвестные команды контроллеру мультиметра — только с согласия владельца.** Байты `0xCC` и `0xEE` (инициализация, калибровка) не отправлять никогда. Проверены только байты 0–6; что делает байт 4 вне переменного напряжения, неизвестно.
- **SCPI-команду `:SECurity` не использовать и не советовать** — она меняет защиту чтения МК, снятие защиты обычно стирает флеш вместе с загрузчиком.
- **Оригинал не трогать.** `firmware/stock/Scope.upp` — единственная исходная точка; все сборки делаются из него.
- **Публикация и установка программ — только по явной просьбе.** Не устанавливай инструменты, не делай `git push` и не меняй настройки без согласия владельца.

## Пожелания владельца

- Общение на русском.
- Палитра — красная: собирай с `--base build/red`.
- Интерфейс только на английском (сборочный скрипт делает это по умолчанию).
- Перед изменением внешнего вида экрана сначала покажи набросок и дождись согласия, потом пиши код.
- Меню графика вызывается клавишей `HOR`; стрелки не использовать.
- Владелец прошивает сам и сообщает результат словами и фотографиями. Проси фото экрана — на них видно больше, чем в описании.

## Окружение

Работа велась на Windows 10, PowerShell 5.1. Нужны:

- Python 3 с пакетом `capstone` (`pip install -r requirements.txt`);
- `arm-none-eabi-gcc` — Arm GNU Toolchain. На исходном компьютере стоит в `C:\Program Files (x86)\Arm GNU Toolchain arm-none-eabi\14.2 rel1\bin` и не добавлен в `PATH`; `tools/build_trend.py` ищет его там сам, иначе берёт из `PATH`.

Python запускался с ключом `-I`. В PowerShell не называй вспомогательные функции `R`: это встроенный псевдоним `Invoke-History`, вызов молча не сработает.

Папки `unpacked/`, `build/` и `analysis/` в репозитории отсутствуют — создай их командами ниже.

## Сборка

```bash
python tools/upp_tool.py unpack firmware/stock/Scope.upp unpacked
```

```bash
python tools/patch_palette.py build red 3=C81010
```

```bash
python tools/build_trend.py ИМЯ --base build/red
```

```bash
python tools/device_checksum.py build/ИМЯ
```

Результат — `build/ИМЯ/Scope.upp`. Последняя команда печатает сумму, которую прибор покажет в `System → About`; всегда сообщай её владельцу — по ней он убеждается, что прошилась именно эта сборка.

Эталон: сборка из чистого репозитория должна побайтно совпасть с `firmware/trend-red/Scope.upp` (сумма `61C604B7`). Если не совпала — разберись почему, прежде чем что-то менять.

Давай каждой сборке новое имя (`trend10`, `trend11`…) и не перезаписывай прежние: владельцу может понадобиться откат.

## Разбор прошивки

```bash
python tools/mklisting.py
```

Создаёт `analysis/mcu.lst` (полный листинг, около 5 МБ) и `analysis/functions.txt` (индекс функций: вызовы, периферия, строки). Листинг большой — ищи в нём поиском, целиком не читай.

```bash
python tools/hds.py func 0801bb10
```

Другие команды `hds.py`: `dis АДРЕС [N]`, `xref АДРЕС`, `calls АДРЕС`, `hex АДРЕС [ДЛИНА]`, `ptrs АДРЕС [N]`. Код прошивки собран почти без оптимизации, читается легко, но функции длинные: фильтруй вывод по `cmp`, `bl`, `tbb`, `.word`.

Приёмы, которые сработали:

- Строки ищутся через `adr`, а не через литералы — в индексе функций их может не быть, ищи по листингу.
- Таблицы переходов `tbb`: цель = адрес после команды + 2 × байт таблицы.
- Чтобы понять назначение кода клавиши, сравни одну и ту же клавишу в обработчиках трёх режимов.
- Если в прошивке есть «мёртвый» код для какой-то возможности (так было с частотой), сначала попробуй оживить его, а не писать свой.

## Как встроена надстройка

Код — `src/trend.c`, скрипт компоновки — `src/trend.ld`. Сборочный скрипт компилирует его, кладёт поверх таблицы иероглифов 18 px и заменяет пять команд `bl` в штатном коде (список `HOOKS` в `tools/build_trend.py`).

Жёсткие ограничения:

- **Флеш:** `0x0804A510…0x0804E400`, занято около 3,5 КБ из 15,6 КБ. Ещё 2,1 КБ свободно за концом образа (`0x0807C7BC…0x0807D000`); дальше лежат настройки прибора — туда нельзя.
- **ОЗУ: свободного нет.** Состояние занимает `0x2000FDEC…0x2000FFF8`, счётчик времени — `0x2000FFF8`. Любое новое поле в `struct state` требует что-то убрать (например, уменьшить `NPT`) и пересчитать, что структура не налезла на счётчик.
- **Нет `.data` и `.bss`:** глобальных и статических изменяемых переменных быть не может — компоновщик это проверяет. Всё состояние — в `struct state`. Константные таблицы допустимы.
- **Нет библиотек:** ни `libc`, ни `libgcc`. Не используй `double`, 64-битную арифметику, `memcpy`, `printf` — скрипт остановится на неопределённом символе.
- **При изменении `struct state` меняй `MAGIC`** — иначе после прошивки останется мусор от прежней раскладки.
- **`trend_tick` выполняется в прерывании** раз в миллисекунду во всех режимах: там только инкремент и переход.

## Как добавить возможность

1. Найди в штатном коде место, где нужные данные уже готовы. Не бери сырые поля, если прошивка их потом обрабатывает: первая версия графика читала сырое значение и показывала «320.0» вместо `OL` и неверные нули.
2. Если нужен новый перехват — выбери команду `bl`, добавь её в `HOOKS` с исходной целью (скрипт проверит, что на этом месте именно она) и объяви функцию в `trend.c`. Замена должна вызывать штатную функцию с теми же аргументами.
3. Напиши код, уложившись в ограничения выше.
4. Собери, пройди «Проверку перед выдачей», сообщи владельцу сумму и что именно проверить на приборе.
5. После подтверждения обнови `docs/NOTES.md`, а если это новая «последняя версия» — `firmware/trend-red/`, `firmware/trend-blue/` и таблицу сумм в `README.md`.

### Опыты на приборе

Когда поведение железа неизвестно, делай пробную сборку: минимальное действие по кнопке и вывод сырых данных на экран (в меню графика уже есть строка байтов последнего кадра мультиметра). Объясни владельцу риск, дождись согласия, дай пошаговый порядок действий и попроси фото после каждого шага. Меняй одну вещь за раз.

## Проверка перед выдачей

- Сборочный скрипт отработал без ошибок: он сам проверяет исходные цели перехватов, отсутствие лишних изменений в образе, размер и суммы пакета.
- Размер образа МК не изменился (`0x06FFBC`).
- В надстройке нет вызовов наружу, кроме известных адресов штатных функций.
- Все обращения к ОЗУ и флеш — по адресам из `docs/NOTES.md`; новые адреса подтверждены дизассемблером.
- В отчёте владельцу: что изменено, чего ждать на экране, что осталось догадкой, ожидаемая сумма.

## Ошибки, которые уже были

- **Счётчик времени.** Взятый из прошивки счётчик оказался не свободно идущим, и график стоял. Свой счётчик — в `trend_tick`.
- **Точки по отсчётам вместо часов.** Мультиметр выдаёт отсчёт раз в ~286 мс, окно «30 с» растянулось до 69 с. Точки надо нарезать по времени.
- **Автоповтор клавиш.** Удерживаемая клавиша шлёт события непрерывно; действие выполняется только после паузы 300 мс.
- **Смена диапазона.** При автодиапазоне приходят ложные нули — три отсчёта после смены пропускаются; история не стирается, а пересчитывается.
- **Удержание (Hold).** Штатная строка показания продолжает обновляться — надстройка хранит свою копию и замораживает её.
- **Коды клавиш угаданы неверно дважды** (`HOR` и `Trig`, флаг V/mV). Догадки о кодах и полярности флагов всегда помечай и проси проверить.
- **Близкие цвета.** Фиолетовый вместо синего на этом экране не отличить; для проверки бери резко другой оттенок.
- **Память за концом образа.** Первая версия лежала там и упёрлась в страницу настроек; поэтому код переехал на место шрифта.

## Что можно делать дальше

Идеи, которые обсуждались с владельцем, но не сделаны:

- относительный режим (Δ) на постоянном напряжении отдельным пунктом меню — та же команда, байт 5;
- частота на переменном токе (поведение байта 5 там не проверено — нужен опыт);
- сохранение настроек графика между включениями;
- звуковой сигнал при выходе значения за порог;
- автоматическое чередование напряжения и частоты;
- запись измерений в CSV на внутренний диск;
- сохранение истории при переходе Ω → kΩ → MΩ, единицы на подписях шкалы.
